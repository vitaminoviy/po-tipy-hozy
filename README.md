# Тихий дом — Prototype 0.6

Минимальный играбельный 3D-прототип уютного обустройства дома для браузера и среды Telegram Mini App. React, TypeScript, Three.js, React Three Fiber, Drei, Vite. Репозиторий `https://github.com/vitaminoviy/po-tipy-hozy.git` был пуст на момент начала работы; существующий код не удалялся.

## Запуск

Нужны Node.js 22+ и pnpm 11.25.0 (при необходимости: `npm install -g pnpm@11.25.0`).

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес из терминала, обычно http://localhost:5173. Для production-сборки: `pnpm build`, затем `pnpm preview`. Готовая статическая сборка находится в `dist/`; сервер разработки для публикации не используется.

### Быстрый запуск и остановка Windows

Дважды нажмите **`Запустить игру.bat`** в корне проекта. После проверки Node.js/pnpm launcher запускает Vite в независимом фоновом процессе, ждёт маркер проекта и готовность страницы, открывает **http://localhost:5173/** один раз и автоматически завершает окно CMD. Закрытое окно запуска больше не останавливает игру. Можно пользоваться обычной локальной ссылкой. Если этот проект уже работает, сервер повторно не запускается. Файл определяет свою папку автоматически, поддерживает другой рабочий каталог, пробелы, кириллицу и `&` в пути.

Чтобы остановить сервер, дважды нажмите **`Остановить игру.bat`**. Он проверяет текущий проект, PID, уникальный идентификатор экземпляра и случайный ключ остановки, затем просит сам Vite закрыть HTTP/WebSocket, наблюдатели и рабочие процессы. После завершения сервера и фонового процесса выводится результат; нажмите любую клавишу, чтобы закрыть окно. Повторная остановка безопасна. Скрипт не ищет и не завершает все Node.js-процессы и не использует PID из файла как цель taskkill. Команда `pnpm dev` сохраняет обычный запуск в терминале; его можно завершить Ctrl+C или новым BAT остановки, если он запущен с актуальным dev-плагином.

Фоновый worker запускается стандартным Node.js `spawn` с `detached: true`, скрытым собственным окном, независимым выводом в файл и `unref()`. Это отдельный процесс, который переживает завершение CMD и launcher. На Windows одновременные старты/остановки сериализуются именованным каналом ОС; после аварии или перезагрузки канал автоматически освобождается. Службы Windows, автозагрузка, администраторские права и новые программы не нужны.

Служебные файлы находятся в игнорируемом `node_modules/.cache/`:

- `quiet-home-server-5173.log` — время запуска и сообщения/ошибки фонового Vite; дописывается при новых запусках.
- `quiet-home-server-5173.json` — последний PID, идентификатор экземпляра и локальный ключ остановки. Запись сохраняется после остановки для диагностики; при новом запуске заменяется атомарно. После перезагрузки или неожиданного завершения старая запись не считается доказательством работающего сервера. PID проверяется вместе с маркером живого экземпляра. Даже повторно использованный PID не становится целью завершения.

Маркер `/__quiet-home_identity` сообщает репозиторий, SHA-256 канонической папки, PID и идентификатор экземпляра; секретов и исходного пути в нём нет. Локальный ключ остановки не публикуется в маркере/логе и не коммитится. `/__quiet-home_stop` принимает только POST с этим ключом; без него остановка запрещена. Оба endpoint относятся только к серверу разработки, в production-сборку не входят. Если запись повреждена/подменена или остался сервер со старым dev-плагином, остановка безопасно отказывается вместо принудительного завершения; для старого ручного `pnpm dev` используйте Ctrl+C в его окне.

Если порт занят чужой программой, ни один BAT её не останавливает и не открывает её страницу. Другой порт автоматически не выбирается; проверяется также IPv6, чтобы `localhost` не указывал на чужой сайт. При ошибке запуска окно остаётся с сообщением; для диагностики доступен лог. Зависимости не переустанавливаются: если они отсутствуют, один раз выполните `pnpm install --frozen-lockfile`. При отсутствии Node.js нужен Node.js 22+; при отсутствии pnpm — `npm install -g pnpm@11.25.0`.

Для автоматических проверок используйте `& '.\Запустить игру.bat' --no-browser` или `node scripts/launch-game.mjs --no-browser`: сервер тоже запускается в фоне, но личный браузер не открывается. Остановка без ожидания клавиши: `& '.\Остановить игру.bat' --no-pause`. Дополнительный `--port ЧИСЛО` предназначен для изолированных тестов; пользовательский адрес всегда 5173. Русский вывод — UTF-8, BAT сохраняются с CRLF. Открытие обычного браузера остаётся разрешённым только при ручном запуске пользователя; автоматические браузерные проверки используют изолированный headless Chromium.

Проверки выполнены на **Windows 11 Pro, build 26300**: настоящий CMD завершается, HTTP игры остаётся доступен, повторный BAT использует тот же экземпляр, остановка завершает Vite/worker, затем возможен новый старт. Проверены одновременные запуски, занятый порт, устаревшая/подменённая/повреждённая запись, аварийное завершение, ошибки Vite и успешный запуск/остановка в пути с пробелами, `&` и кириллицей. Перезагрузка моделируется оставшейся старой записью; настоящий компьютер не перезагружался. Windows 10 и реальное открытие личного браузера в автоматических проверках не тестировались.

После каждого задания Codex по возможности оставляет актуальный сервер, проверяет адрес и предоставляет локальную ссылку и встроенный предпросмотр. Статус встроенного предпросмотра сообщается отдельно: `queued` означает очередь, а не подтверждённую загрузку страницы. Если он недоступен, откройте локальную ссылку самостоятельно или используйте BAT. Это сервер текущего компьютера, не публичная Telegram-ссылка. Постоянные правила разработки закреплены в `AGENTS.md`.

## Что есть

- Одноэтажный дом 10 × 7 м: гостиная, спальня, перегородка с проходом, окна, входная дверь. Крыши нет; передние стены срезаны. Кнопка скрывает стены для свободного доступа к мебели с любого ракурса.
- 13 предметов из примитивов Three.js: прежняя мебель и два ковра, прикроватная тумба, самостоятельные книга, чашка и декоративная коробка. Все предметы можно выбирать, переносить и поворачивать; мелкие вещи крепятся к подходящим поверхностям.
- Ортографическая камера с изометрическим начальным ракурсом, вращением, перемещением и масштабом; возврат к исходному виду.
- Свободный перенос со смещением точки захвата, порогом начала drag в 4 экранных пикселя и мягкой привязкой к сетке 0,25 м. В пределах 1,2 см координата удерживается на линии, до 3 см плавно переходит к свободному движению. Коллизии определяют цвет и возможность установки, не переключают координаты предпросмотра: если привязанная позиция красная, отведите предмет немного дальше от препятствия.
- Более точные границы помещений и меньший резерв прохода дают больше полезной площади. Стены и проходы продолжают ограничивать мебель. Габариты кровати, комода и растения учитывают видимые выступы.
- Единственный зелёный/красный контур и модель в текущей позиции во время переноса. Исходная позиция не отображается; контур — одна плоская рамка без пересечения граней и записи в буфер глубины. Недопустимый drag возвращает предмет в последнюю допустимую позицию этого переноса; недопустимый поворот установленной мебели отменяется.
- Более контрастные материалы и тени, временная панель выбора, живые координаты предпросмотра и подсказки.
- Адаптивный интерфейс и начальный масштаб для узких экранов; WebGL fallback и обработка ошибки сцены.

## Уборка 0.4.1

В доме **9 предметов мусора: 5 в гостиной и 4 в спальне**. Это скомканная бумага, пустые картонные упаковки, бумажные обёртки и жестяные банки — простые геометрические модели без внешних ассетов. Книга, чашка и декоративная коробка остаются обычным декором. Начальные положения мусора сохранены.

Вёдра гостиной и спальни теперь входят в общий список объектов (всего 15). В режиме **«Перемещение»** выбирайте и перетаскивайте их мышью либо используйте «Переместить» и щелчок по полу. Действуют обычные зелёный/красный предпросмотр, мягкая привязка, коллизии, Q/R, Enter/Esc и undo/redo. Ведро остаётся в своей исходной комнате, стоит на полу/ковре и не помещается внутри мебели. Во время приёма мусора перенос принимающего ведра блокируется до завершения или отмены. Геометрия ведра не переделывалась.

1. Включите существующий режим **«Взаимодействие»** кнопкой или Tab.
2. Наведите курсор на мусор: появится кольцо выделения. Нажмите ЛКМ. Выбранный предмет подсвечивается на исходном месте; подсказка предлагает нажать на ведро. Удерживать кнопку не нужно. Зона нажатия размером 0,5 × 0,5 м удобнее видимой бумаги или банки.
3. Нажмите на ведро. Мусор приподнимается, летит по дуге к его **актуальному отверстию**, опускается внутрь и исчезает после завершения. Ориентир — **720 мс** отрисованного времени; при редких кадрах движение может занять дольше. Масштаб сохраняется в середине полёта и уменьшается только на входе в ведро. После прибытия ведро коротко реагирует, а прогресс исходной комнаты обновляется. Ведро не принимает мебель и декор; пустой клик даёт подсказку.
4. **Esc** отменяет выбор или ещё не завершённую анимацию. Выбор другого предмета, смена режима и переход по истории также отменяют незавершённую уборку. Мусор остаётся в комнате; новый шаг истории не создаётся.

**Быстрая уборка: Shift + ЛКМ по мусору** в любом из двух существующих режимов, когда не идёт перенос другого предмета. Сразу выбирается ближайшее свободное ведро **той же комнаты**, с учётом его текущего положения. Если подходящего ведра нет, мусор остаётся на месте и выводится подсказка. Сочетание не утилизирует мебель или декор. Отдельный режим не нужен. Одновременно выполняется один полёт: повторные быстрые клики дают подсказку ожидания и не теряют предметы. Обычный способ «выбрать → ведро» вызывает ту же функцию утилизации. Увеличенная зона попадания активна только при взаимодействии или удержании Shift, сохраняя обычный захват ковров.

Счётчики рядом с названиями комнат вычисляются из реальных записей мусора. Во время полёта прогресс не увеличивается. После последнего предмета комнаты появляется «Комната очищена от мусора!». При обычном выборе ведра другой комнаты прогресс, как прежде, относится к исходной комнате мусора; быстрый способ всегда выбирает ведро своей комнаты. Уборка не блокирует расстановку мебели; только само ведро занимает небольшой круглый участок пола. Мусор не добавлен в препятствия размещения.

У мусора собственные стабильные ID, тип, комната, X/Z и одно состояние: `room`, `selected`, `disposing` или `disposed`. Высота опоры вычисляется по полу и коврам. Траектория — сглаженная квадратичная дуга с ограничением высоты, без физики и поиска пути. Во время полёта объект недоступен для повторного подбора; синхронная блокировка защищает от двойного старта. Завершение сообщает сам 3D-компонент после кадра в конечной точке, независимого таймера удаления нет. При отмене/смене режима/undo операция теряет актуальность и мусор возвращается. После завершения запись получает `disposed` и исключается из рендера и взаимодействий.

**Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z** работают в общей истории мебели, вёдер и уборки: одна завершённая утилизация — одно действие. Отмена возвращает мусор на исходное место без устаревшего состояния выбора. Повтор восстанавливает завершённое состояние без нового полёта. Новое действие после отмены очищает ветку повтора. Лимит истории остаётся 100 действий.

При полной перезагрузке страницы мусор и прогресс возвращаются к исходным. Сохранений, сервера, наград, пыли, пятен, мытья окон и покраски нет. Все девять исходных предметов доступны из начального ракурса при скрытых стенах, без перестановки мебели; при перекрытии стеной или позже перемещённой мебелью поверните камеру. Управление камерой и мышиное размещение мебели не менялись.

## Размещение предметов

Книгу, чашку и коробку можно поставить на пол и ковёр, на столешницу, в открытый ящик, **на кровать, диван и кресло**. Выберите вещь и нажмите «Взять предмет» или E, наведите на нужное место и подтвердите щелчком/Enter; обычное перетаскивание мышью также работает. На полу координаты мировые, `surfaceId`, `surfaceZone` и `drawerIndex` отсутствуют; в панели показано «На полу». Высота рассчитывается по верхней поверхности пола/ковра/его полос, с техническим зазором 1 мм. Ковёр не становится родителем вещи: при его переносе X/Z вещи сохраняются, опора по высоте пересчитывается.

На кровати используются плоские участки покрывала, его приподнятой складки и доступные участки матраса. На диване — две подушки сиденья, на кресле — сиденье. Высоты и размеры зон берутся из существующей геометрии; технический зазор над мягкой поверхностью — 1 мм. Проверяются края зоны, спинки, подлокотники, подушки и складка: красный предпросмотр означает, что вещь не помещается или пересекает выступ. Верх подлокотников и подушек не является отдельной опорой. Поверхность выбирается лучом под курсором; чтобы добраться до закрытого мебелью участка пола, поверните камеру. Положение и опорную зону выбирайте мышью.

У мягкой поверхности сохраняются `surfaceId` и `surfaceZone`, а X/Z и поворот задаются относительно зоны. Вещи следуют за переносом и поворотом мебели, включая отмену и повтор. Зоны расширяются в `src/placementGeometry.ts`, без изменения системы истории или моделей.

Контакт мелких вещей с мебелью проверяется по составным объёмам и пересечению по высоте: например, высокая спинка не раздувает препятствие у пола, а нижняя полка не блокирует книгу, которая проходит под ней. У чашки отдельно проверяются круглый корпус и ручка. Запас мелкой вещи до мебели — **3 мм** вместо прежних 1,2 см. Между мелкими вещами остаются 1,2 см, до края поверхности — 1 см. Между крупной мебелью оставлен технический зазор **2 см** вместо прежних 22 см; полные видимые габариты не уменьшены, повороты учитываются; внутренние запасы ящиков остались 2,5/3,5 см. Объекты не складываются друг на друга, полноценной физики нет.

При отпускании перетаскиваемой вещи в красной зоне выбирается последняя допустимая позиция именно текущего переноса, вместе с поворотом и привязкой к поверхности/ящику. Если промежуточной позиции не было, используется исходная. Это одно действие undo/redo; предпросмотр не создаёт записей истории. Esc полностью отменяет перенос. Enter и щелчок в режиме «Взять предмет» по-прежнему не подтверждают красный предпросмотр — можно уточнить позицию.

## Взаимодействия 0.3.2

Кнопки «Перемещение» / «Взаимодействие» и клавиша **Tab** переключают режим. Смена режима отменяет текущий предпросмотр. В режиме перемещения ЛКМ переносит предмет; в режиме взаимодействия ЛКМ на ящике открывает его, на торшере переключает свет, на мелком предмете начинает его размещение. Ящик в режиме взаимодействия не запускает перенос комода. Выбранной мебелью также можно управлять контекстными кнопками внизу.

**E** выполняет действие выбранного предмета в обоих режимах: включает/выключает торшер, берёт мелкую вещь, открывает/закрывает ящик. У мебели с несколькими ящиками E закрывает первый открытый, а если все закрыты — открывает первый; любой конкретный ящик по-прежнему выбирается мышью или существующими кнопками. Без выбранного предмета и во время переноса E ничего не делает; удержание не повторяет действие. Q/E больше не поворачивают камеру, Q/R работают как горячие клавиши поворота мебели только во время переноса. Вне переноса доступна прежняя кнопка «Повернуть».

У большого комода три независимых ящика, у существующей прикроватной тумбы — один. Корпуса полые, ящики плавно выдвигаются до 28 см через открытые проёмы. Перед открытием консервативно проверяется свободное место впереди. При переносе ящики закрываются; успешный перенос/поворот сохраняет их закрытыми одним действием истории. Отмена предпросмотра возвращает прежнее состояние.

### Хранение

Откройте нужный ящик, выберите книгу, чашку или коробку и нажмите «Взять предмет». Наведите на дно открытого ящика: зона захвата расширена на 14 см вокруг его внутренней области. Либо нажмите «В ящик N: …» для выбора центра и нажмите Enter; другую точку выберите мышью. Расширение зоны захвата не расширяет допустимые границы: красный контур показывает выход за стенки, пересечение или неподходящую высоту. Щелчок по сцене также подтверждает текущую позицию под курсором.

У каждого ящика свои внутренние размеры и предел высоты. Проверяются повёрнутые габариты, отступ 2,5 см от стенок и 3,5 см между вещами в одном ящике. Ящики комода вмещают все три тестовых предмета; в тумбу помещаются книга и чашка, коробка слишком высокая. Центральная позиция может быть занята — передвиньте предпросмотр или выберите другой ящик.

Вещь хранит `surfaceId`, `drawerIndex`, локальные X/Z и угол. Она следует за перемещением и поворотом мебели, а при открывании использует то же значение анимации, что и сам ящик. Закрытое содержимое не отрисовывается и не перехватывает клики; записи предметов остаются в состоянии. Для извлечения снова откройте ящик, нажмите на вещь или «Достать: …» в контекстных действиях мебели и перенесите её на столешницу или в другой открытый ящик. Кнопка извлечения позволяет обойти перекрытие небольшого предмета фасадом. Взять предмет из закрытого ящика нельзя. Хранение и извлечение поддерживают отмену/повтор.

Торшер плавно изменяет яркость настоящего тёплого PointLight и цвет/свечение плафона. Свет и переключение работают после переноса, отмены и повтора. Дополнительные тени от PointLight и тяжёлые эффекты не используются.

Книга и чашка начинают на журнальном столе, коробка — на комоде. Выберите вещь и нажмите «Взять предмет» или нажмите на неё в режиме взаимодействия. Наведите на стол, тумбу или комод и щёлкните. Для точного переноса также можно зажать ЛКМ на вещи в режиме перемещения. На свободной части столешницы появляется зелёный предпросмотр; выход за край, соседний декор и отсутствие поверхности дают красный контур. Недопустимая установка не применяется; Esc отменяет перенос.

Поверхность выбирается по пересечению луча мыши с зарегистрированными горизонтальными столешницами. Проверяются габариты с поворотом, запас 2,5 см до края и зазор 3,5 см между мелкими вещами. Свободное перемещение по столешнице не принуждается к крупной напольной сетке. Вещи хранят локальные X/Z и угол относительно мебели, поэтому следуют за её переносом, поворотом и предпросмотром. При смене поверхности сохраняется мировой угол. Вещь не падает на пол, не опирается на другую вещь и не использует физический движок.

**Ctrl+Z** отменяет последнее изменение; **Ctrl+Y** или **Ctrl+Shift+Z** повторяет его. Есть компактные кнопки ↶ / ↷. История включает перенос/поворот мебели, размещение вещей, состояние каждого ящика и торшера. Новый успешный шаг после отмены очищает повтор; выбор предмета, камера, смена режима и отменённые/недопустимые переносы не создают шагов. Активный перенос отменяется перед переходом по истории. Хранятся до 100 действий в памяти, без сохранения между перезагрузками.

### Камера и перенос с клавиатуры

WASD перемещает камеру относительно текущего ракурса со скоростью 5,5 м/с (в 2,2 раза быстрее 0.3.1); Shift ускоряет до 13,2 м/с. Зажатая СКМ вращает по горизонтали и меняет вертикальный угол, ПКМ перемещает по полу, колесо меняет масштаб, Home возвращает исходный вид. Ортографическая проекция сохранена. Вертикальный угол ограничен диапазоном примерно 15,5–70° над полом без переворотов; горизонтальный поворот свободный. Точка наблюдения ограничена X=±4 м и Z=±3 м; ПКМ внутри сцены не открывает меню браузера. Ускорение/торможение рассчитываются по времени с точным интегрированием, шаг длинного кадра ограничен 50 мс. Играть можно преимущественно мышью, используя существующие контекстные кнопки.

Предметы перемещаются **только мышью**: потяните предмет с зажатой ЛКМ либо выберите «Переместить» / «Взять предмет» и укажите место курсором. WASD всегда предназначены камере, даже при выборе предмета и предпросмотре установки щелчком. Только во время переноса с зажатой ЛКМ движение камеры клавишами приостанавливается; отпускание или отмена сразу возвращает управление. Shift ускоряет только камеру. Q — против часовой стрелки, R — по часовой стрелке: короткое нажатие 7,5° за 140 мс, удержание — непрерывно 75°/с во время переноса; Enter подтверждает допустимое положение, Esc отменяет. Зелёный/красный контур, мягкая привязка и возврат к последней допустимой позиции сохранены. Вся сессия переноса с поворотами создаёт один шаг истории. При вводе текста в input, textarea, select или contenteditable игровые клавиши игнорируются.

## Размещение и категории

| Категория       | Предметы                                   | Правила                                                                                  |
| --------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Мебель          | Диван, кресло, стол, кровать, комод, тумба | Прямоугольные контуры, технический зазор 2 см между предметами мебели                    |
| Декор           | Растение, торшер                           | Круглые контуры; 8 см до мебели, 6 см до другого декора                                  |
| Напольный декор | Ковры гостиной и спальни                   | Лежат на полу, допускают перекрытие мебелью и друг другом; остаются внутри одной комнаты |
| На поверхности  | Книга, чашка, коробка                      | Границы столешницы и зазоры между вещами; следуют за родительской мебелью                |

Расстояние считается между контурами: прямоугольник–прямоугольник, окружность–прямоугольник или окружность–окружность. Диагональное положение не блокируется грубым расширенным квадратом. Причина отказа видна внизу экрана, включая требуемый отступ. Поворот свободный, без обязательной угловой привязки, в том числе во время переноса.

Оба ковра теперь самостоятельные объекты состояния, а не часть House. Они перемещаются и поворачиваются на фиксированной высоте над полом; размещение мебели поверх ковра и перенос ковра под мебель допустимы в обе стороны. Перенос ковра не перемещает стоящую на нём мебель. Ковры могут покрывать пол прохода, но не пересекать стены/перегородку. Два немного различающихся уровня поверхности уменьшают мерцание при перекрытии ковров.

Если предмет закрыт мебелью или стеной, выберите его в списке и нажмите «Переместить». Наведите указатель на пол: зелёный контур разрешает постановку щелчком, красный её блокирует. При недопустимом щелчке режим остаётся активным; Esc или «Отменить» возвращает исходное состояние. Этот способ особенно удобен для ковров под кроватью. Обычный перенос зажатой ЛКМ также сохранён.

## Telegram Mini App

Подключён официальный JS bridge. При наличии Telegram вызываются `ready()`, `expand()` и опциональный `disableVerticalSwipes()`. В обычном браузере приложение работает самостоятельно. Подключение bridge соответствует [документации Telegram](https://core.telegram.org/bots/webapps); захват и события 3D-сцены основаны на [документации React Three Fiber](https://r3f.docs.pmnd.rs/api/events).

Для запуска внутри Telegram нужно разместить `dist/` на HTTPS-хостинге и указать URL в настройках Mini App бота через BotFather. Бот и хостинг в этой задаче не создавались. Проверен вызов bridge через заглушку в Chrome; реальный Telegram Desktop / мобильный WebView не проверялся. Авторизация, initData и сервер для этой локальной версии не используются.

## Ограничения текущего прототипа

- Уборка ограничена мусором и двумя участками пола. Нет мытья окон/стен/мебели, покраски, воды, сохранений, магазина, экономики и мультиплеера. Перезагрузка восстанавливает стартовую расстановку, мусор и грязь.
- Коллизии мелких вещей проверяют пересекающиеся по высоте примитивы, без физики, деформации ткани и штабелирования. Ручка чашки и растительные формы остаются консервативными объёмами, отверстия и точные треугольники не моделируются. Предметы перемещаются только мышью; проверяется положение предпросмотра и установки. Книга, чашка и коробка размещаются на полу/коврах, жёстких поверхностях, матрасе/покрывале/сиденьях и в подходящих открытых ящиках. Для мягкой мебели доступны только зарегистрированные плоские зоны. Ковры не являются физическими платформами. Угол поворота произвольный.
- Хранение — один слой вещей на дне. Проверка места перед открытием консервативная; полноценная динамическая коллизия анимируемого ящика с последующими перемещениями другой мебели не моделируется. Содержимое скрывается сразу при команде закрытия и становится доступным после открытия; для мелких перекрытых фасадом вещей предусмотрена кнопка извлечения.
- Причина E23 устранена у дивана, кресла и кровати и проверена в Chrome; реальный Telegram WebView и другие GPU требуют отдельной визуальной проверки.
- Окна и дверь — геометрические декорации, дверь не интерактивна. Стены скрываются общей кнопкой, автоматически по ракурсу не исчезают.
- В production-сборке остаётся предупреждение Vite о размере модуля Three.js (>500 КБ до gzip); общая сжатая JS-загрузка около 326 КБ. Оптимизация загрузки под реальные устройства — следующий этап.
- Нужен WebGL и аппаратное ускорение. Реальные Telegram-клиенты, Safari и мобильные жесты требуют отдельной проверки. Google Fonts и Telegram bridge используют сеть; при отсутствии шрифта есть системный fallback, модели внешних ассетов не требуют.

## Протирание пола — Prototype 0.5

Включите **«Взаимодействие»** кнопкой или Tab. На грязном полу зажмите ЛКМ и двигайте мышь: небольшая губка следует за курсором, стирается только её траектория. Клик и неподвижное удержание ничего не очищают. Отпустите ЛКМ, в том числе вне участка, чтобы закончить жест. Esc, потеря фокуса, скрытие вкладки, отмена указателя и смена режима отменяют незаконченный жест и возвращают его исходную грязь. Уже завершённые жесты сохраняются в сессии.

Два участка расположены на свободном полу перед мебелью: **гостиная — X −3,15 / Z 2,45; спальня — X 1,85 / Z 2,4; оба участка размером 0,95 × 0,65 м**. Они доступны с исходной расстановкой и стенами. Приблизьте камеру колесом для более точного протирания. Полоса «Пол …%» рядом с прежним прогрессом каждой комнаты независима от количества мусора.

Каждый участок хранит собственную маску 96 × 96 байт. Процедурные неоднородные разводы отображаются через CanvasTexture на прозрачной плоскости в 4 мм над полом. Мягкая кисть радиусом 11,5 см очищает расстояние до всего отрезка движения, включая быстрые движения без промежуточных событий. Текстура обновляется максимум один раз за отрисованный кадр; указатель меняет рабочую копию маски, а не состояние всей React-сцены. При завершении компонента текстура освобождается. Процент определяется удалённой суммой исходной непрозрачности; повторение по полностью чистому месту не приносит прогресса. При очистке не менее 95% остатки исчезают за 0,25 секунды; после отпускания ЛКМ показываются 100% и «Поверхность очищена!».

**Один жест — один шаг Ctrl+Z / Ctrl+Y (или Ctrl+Shift+Z)** в общей истории мебели, мусора и пола. История ограничена 100 действиями; снимки переиспользуют неизменённые маски. Новый жест после undo очищает redo. Выбор мебели, камера, ящики, переключение режима и уборка мусора не сбрасывают завершённую очистку. WASD временно приостановлены только на время активного протирания; после отпускания снова управляют камерой. Прежние сочетания и система запуска не изменены.

Грязь не является мебелью и не участвует в коллизиях: поверх неё можно ставить мебель и ковры. Закрытая ими часть не очищается напрямую через предмет; после переноса снова видна оставшаяся грязь. Ограничения: плоский пол, две фиксированные зоны, без физики и постоянных сохранений. События указателя совместимы с будущим сенсорным вводом, но отдельное мобильное управление протиранием пока не проверено на настоящем телефоне/Telegram WebView.

Новые файлы: `src/wiping.ts` — маски, зоны и математика кисти; `src/DirtScene.tsx` — текстуры, указатель, губка и освобождение ресурсов; `tests/wiping.test.ts` и `tests/e2e/wiping.spec.ts` — логика, история и реальные жесты. Визуальные снимки до, после первого движения, частичной и полной очистки обеих комнат сохраняются в игнорируемые `artifacts/05-*.png`.

## Свободное плавное вращение мебели

В существующем переносе **Q вращает против часовой стрелки, R — по часовой стрелке**, если смотреть сверху. Короткое нажатие даёт **7,5° за 140 мс**, удержание после начального перехода — **75°/с**. Обязательной привязки к 0/90/180/270° нет: можно оставить любой достигнутый угол, например 32° или 67°. Кнопка «Повернуть» выполняет тот же плавный короткий поворот выбранного предмета по часовой стрелке. Новых клавиш и режимов нет; WASD остаются камерой.

Вращение интегрируется по времени requestAnimationFrame, а не по системному повтору клавиатуры. Плавный короткий переход имеет единственный управляемый целевой угол; смена направления начинается с текущего положения. После отпускания удержанной клавиши дополнительные повороты не накапливаются. Короткий тап завершает свой небольшой 140-мс переход. При одновременных Q+R вращение приостанавливается; после отпускания одной клавиши продолжается в направлении оставшейся. Esc/смена режима/потеря фокуса прекращают перенос; при вводе текста вращение не работает. Подтверждение фиксирует текущий видимый угол, не заставляя предмет прыгать к ещё не достигнутой цели.

Полные габариты мебели сохранены. На полу используются ориентированные прямоугольники (SAT), точное расстояние между их рёбрами для прежнего зазора **2 см**, а для круглых объектов — окружности. AABB нужны только для проверки внешних границ дома/плоской поверхности; они больше не заменяют повёрнутую форму при проверке соседей. Зоны прохода, входа, ковры и их полосы также учитывают ориентацию. У мелких вещей сохранены составные примитивы и проверки пересечения по высоте. Контур вращается вместе с моделью, зелёный/красный цвет вычисляется для того же угла. При недопустимом отпускании используется последняя допустимая поза с её углом; вне переноса недопустимый поворот кнопкой отменяется.

Диван, кресло, кровать, стол, комод, тумба, ковры, вёдра и прежние поворачиваемые предметы поддерживают дробные углы. Круглое ведро визуально почти симметрично, но угол сохраняется в истории. Предметы на мебели и внутри ящиков остаются в локальных координатах и следуют за повёрнутым родителем. Одно размещение с переносом/поворотом — один шаг undo/redo. Внутреннее поле rotation сохранило прежнюю единицу 90° для совместимости исходной расстановки; дробные значения теперь обрабатываются геометрически, без проверки чётности поворота. Интерфейс показывает угол с точностью 0,1°, состояние хранит полную точность.

Существующие ограничения ящиков, допустимых поверхностей и комнат вёдер остаются. Физики, деформации мягкой мебели, сохранений и новых инструментов нет. Этап свободного вращения выполнен в рамках Prototype 0.5; незавершённых изменений Prototype 0.6 на момент его начала не было. Старые браузерные сценарии используют helper для получения прежних точных четверть-оборотных фикстур через серию новых малых нажатий; новый free-rotation.spec.ts отдельно проверяет настоящие нажатия/удержания Playwright и текущую схему Q/R.

Добавлены 13 unit-тестов и 5 сценариев настоящих нажатий Q/R, включая удержание/отпускание, смену направления, Q+R, ввод текста, blur/Tab, ковры, вёдра и историю. ### Одновременный перенос и вращение

Во время переноса мышью можно удерживать Q/R: предмет непрерывно следует за курсором и одновременно поворачивается. После отпускания клавиши перенос продолжается с сохранённым углом. Точка захвата остаётся прежней; поворот не смещает центр предмета. Работает и перенос с удержанием ЛКМ, и существующий предпросмотр через кнопку «Переместить».

Положение переноса хранится в одном синхронном снимке: обработчики указателя и кадры вращения читают последние координаты и угол до очередного React-рендера. Предпросмотр, проверка размещения, последняя допустимая поза и подтверждение используют этот же снимок. Весь перенос с любым количеством движений и поворотов остаётся одним действием undo/redo. Если взятый мышью предмет только повернули, отпускание ЛКМ также подтверждает результат. Скорость, шаг вращения, SAT, зазор 2 см и управление камерой сохранены.

Проверки одновременного ввода: **119/119 unit/integration-тестов** и **63/63 браузерных сценария** прошли. Новый `simultaneous-placement.spec.ts` содержит 12 сценариев: настоящие одновременные ЛКМ+Q/R с несколькими перемещениями указателя, вращение до первого движения, продолжение после отпускания, восемь типов мебели, смена направления, красная зона/откат, отмена, история и привязанные вещи. Набор свободного вращения сохраняет математическую проверку скорости с шагами времени 30/60/144 FPS. TypeScript, production build, Prettier и git diff --check проходят. ### Prototype 0.5.1 — обработка быстрых перемещений

События pointermove сохраняют последнюю позицию указателя без немедленного расчёта размещения. Уже существующий requestAnimationFrame объединяет эту позицию с текущим углом Q/R и один раз публикует позу для React. Фиксированного ограничения FPS, дополнительной интерполяции позиции и инерции нет. Перед отпусканием ЛКМ, Enter или кнопкой установки последний ожидающий ввод обрабатывается сразу; Esc, потеря фокуса и завершение переноса сбрасывают очередь. Последняя допустимая поза и история учитывают одновременно координаты и угол.

Проверка коллизий неизменна: ориентированные прямоугольники/SAT, прежние объёмы по высоте и зазор 2 см. Не вычисляется невидимый контур невыбранных объектов; повторный расчёт текста/класса footer заменён одним результатом для текущей позы. Массив предпросмотра родительской мебели создаётся один раз за рендер вместо отдельного создания для каждого предмета. Все параметры вращения и клавиши прежние.

## Prototype 0.6 — покраска валиком

Включите «Взаимодействие» (Tab), нажмите «Покраска» и выберите **Кремовый #E9D8BA**, **Шалфейный #A7B7A1** или **Терракотовый #CA8E78**. На доступном участке появляется валик. Удерживайте ЛКМ и двигайте мышь по стене; отпустите ЛКМ, чтобы закончить мазок. Колёсико позволяет приблизиться. Кнопка «Покраска» выключает инструмент и возвращает обычные взаимодействия. Новых клавиш нет.

Для теста доступны два сплошных участка существующих стен размером **2,4 × 1,3** каждый, на высоте **1,5–2,8**:

- `wall-living`: внутренняя сторона левой стены гостиной, центр X −4,902 / Y 2,15 / Z 1,35, выше кресла.
- `wall-bedroom`: сторона перегородки, обращённая в спальню, центр X 0,098 / Y 2,15 / Z −1,65, выше мебели.

Тонкая рамка показывает область работы, пока инструмент включён. Окна/проёмы находятся вне этих зон. Оба участка доступны из исходной расстановки без переноса мебели. При выборе инструмента включается существующее отображение стен. Кнопка скрытия стен убирает и видимые слои, и их попадания указателя; показ стен восстанавливает прежнее покрытие. Новая камера и геометрия дома не создавались.

Каждая стена хранит отдельную маску 96×96 и цвет в общей истории с мебелью, мусором и полом. Swept-кисть вычисляет покрытие вдоль всего отрезка между точками; быстрые мазки не требуют отдельных мешей или физических объектов. При быстром выходе из зоны последняя полоса обрезается по границе, а при возвращении начинается новый отрезок. Маска берёт максимум покрытия, поэтому повторный проход не затемняет цвет и не начисляет повторный прогресс. CanvasTexture загружается при изменении маски, не чаще кадра. Во время движения изменяется личная копия маски и небольшой DOM-индикатор; React получает результат завершённого жеста. Текстуры освобождаются при удалении слоёв. Разрешение маски переиспользуется из механики протирания; алгоритм нанесения добавлен отдельно без переписывания мытья пола.

Процент вычисляется по сумме реально окрашенных alpha-пикселей. Если к отпусканию ЛКМ покрыто не менее **95%**, остаток заполняется до 100% и появляется «Стена покрашена!». Частичная покраска сохраняется после смены режима, вращения камеры, перемещения мебели и других действий внутри сессии.

Цвет закрепляется после первого завершённого мазка. Для другого цвета на этой стене отмените её мазки до исходного состояния. Вторую стену можно красить своим цветом. Выбор другого цвета в палитре не перекрашивает уже нанесённый слой.

**Один непрерывный жест — одно действие истории.** Ctrl+Z/Ctrl+Y (также Ctrl+Shift+Z) восстанавливают маску, цвет, процент и завершение; новый мазок после отмены очищает ветку повтора. Esc, смена инструмента/цвета/режима, скрытие стен, потеря фокуса и отмена указателя отменяют незавершённый мазок. Отпускание ЛКМ вне стены сохраняет уже нанесённую часть. Смена камеры через СКМ/ПКМ отменяет активный жест и сохраняет ранее завершённые мазки. Во время нанесения камера не двигается от удерживаемых клавиш; после отпускания управление восстанавливается.

Ограничения прототипа: два отмеченных участка, один цвет на участок, общий лимит истории 100 действий, простой валик из примитивов. Полная перезагрузка страницы восстанавливает исходное состояние. Мобильный интерфейс и постоянные сохранения пока отсутствуют. Цвет материала зависит от существующего освещения. Оптимизация перемещения мебели Prototype 0.5.1 сохранена; дополнительная оптимизация экстремально быстрых движений отложена на отдельный этап.

Проверки Prototype 0.6: **135/135 unit/integration-тестов** и **79/79 браузерных сценариев по 14 файлам** прошли последовательно в изолированном headless Chromium. Добавлены 16 unit-тестов и 9 браузерных сценариев покраски. TypeScript, production build, Prettier и git diff --check прошли. Просмотрены восемь снимков двух стен (до, полоса ≈12%, частично ≈45%, 100%), вертикальные/диагональные мазки и разрыв при повторном входе. Пиксельная проверка подтверждает сохранение не посещённого валиком участка. Дополнительная проверка живого сервера 5173 получила HTTP 200, два отдельных мазка гостиной 12%→24%, другой цвет спальни 12%, рабочие undo/redo и отсутствие pageerror/console.error. Уборка мусора, пол, ящики, мягкие поверхности, камера, свободные углы и совместный перенос/вращение прошли прежнюю регрессию. Личный Chrome не использовался.
