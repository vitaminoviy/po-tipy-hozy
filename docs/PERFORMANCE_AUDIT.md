# Технический аудит — Prototype 0.9

22.10.2026. Исходная версия: b7eacd60c43a0dfe5281d49e92a4423d311893da.
Изменения ограничены подтверждённой лишней работой React, владением геометрией
мусора, жизненным циклом/viewport оболочки и диагностикой запуска. Схема сохранений
1, размеры масок, SAT/зазоры, скорость вращения и общий RAF переноса не менялись.

## Методика и воспроизведение

Один компьютер Windows, изолированный headless Chromium 156.0.8078.4,
ANGLE Direct3D11, viewport 1440×1000, DPR 1. Перед каждым trial — новый context,
600 мс прогрева, GC через CDP. В каждом сценарии 180 RAF, по три повтора. Сцена
со скрытыми стенами, выбранным журнальным столом в click-to-place переносе.
Slow: одно событие на RAF; burst: восемь событий (1440 за сценарий), резкие смены
направления/диагонали, отдельно удерживаемые Q и R. Реальный ввод мыши проверяют
также прежние rapid-placement и simultaneous-placement browser tests.

```powershell
node scripts/profile-game.mjs before --ref b7eacd6
node scripts/profile-game.mjs after
node scripts/profile-game.mjs resources --soak
```

`--ref` читает старые src через git show в диагностический build, не переключая
ветку и не меняя рабочие файлы. Preview строго на 127.0.0.1:4191, не на пользовательском 5173. Браузер и собственный preview закрываются в finally. Не запускать эти команды
параллельно с тяжёлыми браузерными наборами. Вывод: `artifacts/09/*.json`, CPU profiles,
снимки; в Git они не входят. Профилирующий Vite plugin добавляет счётчики только в
отдельную сборку `artifacts/09/profile-dist`; обычная игра не содержит __audit.

## Продолжительная смешанная сессия и ресурсы

Отдельный bounded soak: **18 циклов за 82,4 секунды**, четыре подтверждённых сброса
(с учётом прогрева). В цикле: перенос/вращение стола, ящик и книга, мусор, губка,
валик/цвет, укладка, undo/redo, записка. Внутри партии нет reload между действиями;
после первой партии сверяется сохранённый мир до/после reload. Снимаются каденция,
GC heap, DOM, renderer counters. Все операции — только в тестовом context.

Во всех 18 контрольных окнах P95 RAF 16,7–16,8 мс; постоянного ухудшения каденции
не обнаружено. Ошибок JS/console.error нет, digest сохранения совпадает после reload.
После каждого сброса: 411 DOM nodes, один активный GL-контекст, 250 загруженных
геометрий, 15 текстур, 8 shader programs; основная сцена 349 objects / 257 meshes,
248 main-pass draw calls. Эти числа больше короткого benchmark из-за видимых стен.

До исправления E113 восемь сбросов без reload давали nodes 790→3822 и listeners
272→488 даже без SDK. Heap snapshot установил путь от глобальной геометрии бумаги
через dispose listeners к старым GL context/Canvas. Геометрия теперь одна на Cleaning
и явно освобождается при размонтировании. Тот же тест: nodes 418→411 и далее 411,
listeners 245→245. Сохранения и сам механизм сброса ради этого не переписывались.

В смешанном soak post-GC heap изменился примерно с 11–12 до 15 МиБ. После
взаимодействий listeners увеличились однократно с 246 до 259 и далее не росли;
DOM и GL counters стабильны. Это **не доказательство абсолютного отсутствия любых
утечек**: вклад JIT/кешей и остаточная разница heap полностью не классифицированы.
Наблюдение P3: повторить более долгий профиль на реальном целевом устройстве,
особенно после новых ассетов. Обнаруженное линейное удержание старого Canvas устранено.

## Надёжность и оставшиеся риски

- Сохранения: формат и массивы не менялись. Полная регрессия включает частичные маски,
  произвольные углы, содержимое ящиков, полный пол, undo/redo, reset, отказы и две
  вкладки. Личный IndexedDB не читался и не очищался.
- Lifecycle: новый тест до исправления показывал движение камеры при hidden без
  blur; после исправления камера и незавершённый ремонт отменяются. Потеря/возврат
  WebGL проверены по данным **и пикселям**, не только старому dataset атрибуту.
- E97 (P2): причина не установлена, ошибка не закрыта. Восемь диагностических
  повторов трёх startup/crash/restart tests прошли, обычная регрессия — без trace.
  BAT не менялись. `QUIET_HOME_DIAGNOSTICS=1` пишет только безопасные сведения о
  неудачных TCP/bind/identity probes, без identity response/stopToken.
- E80 (P2): экстремальные субъективные рывки физической мыши не воспроизведены
  этими desktop сценариями. Не обещается устранение на всех частотах/устройствах.
- W01: Three.js chunk больше 500 КБ; разделение/ассеты оценивать перед публикацией,
  не устраивать глобальный рефакторинг ради предупреждения.
- Реальные Telegram Android/iOS, touch-эргономика, GPU timing/VRAM и батарея не
  проверены. Проект не объявляется готовым к публичному выпуску.

Дальнейший этап: [подготовка графики](VISUAL_UPGRADE_READINESS.md) и
[матрица Telegram](TELEGRAM_READINESS.md). Не заменять модели/свет одновременно
с изменением логики сохранений или коллизий — это затруднит диагностику регрессий.

JSON/CPU profiles: artifacts/09/sofa-before, sofa-after (промежуточный),
sofa-indexed (финальный), вне Git. Коллизии и трасса координат не менялись.

Прямая замена выявила подтверждённую CPU-проблему: Raycaster перебирал 18 060
треугольников на каждое событие. В CPU samples преобладали intersectTriangle,
getVertexPosition/fromBufferAttribute и векторные операции. Пакет из восьми
событий вырос примерно с 2,5 до 11–12 мс; в части окон терялись React-публикации
позиции. Это устранено статическим CPU AABB-индексом в meshPicking.ts.
Индекс отбирает листья, но конечный тест выполняет штатный Mesh.raycast по
исходным треугольникам. Точки попадания, UV, faceIndex и owner проверены против
нативного raycast при 0°, 37,5° и 90°. Рисуемая геометрия не упрощалась,
SAT и игровые границы не менялись, дополнительных библиотек и draw calls нет.
Индекс и его CPU-геометрии освобождаются вместе с владельцем.
