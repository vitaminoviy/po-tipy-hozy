# Журнал ошибок

Дата: 19 октября 2026 года. Журнал включает ошибки реализации, настройки среды и проверок. Проверки относятся к локальному Chrome и сборке; проверка в реальном Telegram ещё не проводилась.

## E01 — Рабочая папка не являлась Git-репозиторием

- **Описание:** первые `git status` и `git remote` завершились ошибкой.
- **Причина:** предоставленная рабочая папка была пустой, репозиторий ещё не клонировали.
- **Исправление:** выполнен `git clone https://github.com/vitaminoviy/po-tipy-hozy.git .`. Удалённый репозиторий также оказался пустым.
- **Проверка:** `git remote -v` указывает на требуемый адрес; `git status` работает.
- **Предотвращение:** проверять наличие `.git` до команд, требующих репозитория.

## E02 — npm отсутствует в PATH среды

- **Описание:** команда `npm --version` не найдена при наличии Node.js.
- **Причина:** среда содержит отдельный bundled runtime, не стандартную установку Node.js с npm.
- **Исправление:** использован доступный bundled pnpm, добавлены lockfile и версия менеджера пакетов.
- **Проверка:** установка зависимостей, build и test выполняются через pnpm.
- **Предотвращение:** обнаруживать доступные инструменты перед установкой; документировать Node.js 22+ и pnpm 11.25.0.

## E03 — Заблокирован postinstall esbuild

- **Описание:** pnpm завершал установку с `ERR_PNPM_IGNORED_BUILDS`.
- **Причина:** pnpm 11 требует явного правила `allowBuilds`; первоначально использована устаревшая настройка `onlyBuiltDependencies`.
- **Исправление:** в `pnpm-workspace.yaml` разрешён build только для esbuild. После автоматического добавления pnpm placeholder возник повторный ключ `allowBuilds`; дубликат удалён, осталось одно правило `esbuild: true`.
- **Проверка:** повторный `pnpm install` успешно выполнил postinstall; production build проходит.
- **Предотвращение:** учитывать версию pnpm, проверять автоматически изменённый YAML. См. [официальные настройки pnpm](https://github.com/pnpm/pnpm.io/blob/main/docs/settings/build.md).

## E04 — Недоступный прямой импорт типа OrbitControls

- **Описание:** TypeScript выдавал TS2307 для `three-stdlib`.
- **Причина:** пакет является транзитивной зависимостью Drei и не доступен как прямой импорт при изолированной структуре pnpm.
- **Исправление:** тип ref выведен через React `ComponentRef<typeof OrbitControls>` из уже используемого компонента Drei.
- **Проверка:** `pnpm typecheck` и `pnpm build` проходят.
- **Предотвращение:** не импортировать транзитивные зависимости напрямую; выводить тип из публичного API.

## E05 — Комод перекрывал вход при старте

- **Описание:** тест валидности стартовой расстановки отклонил комод.
- **Причина:** левый край комода пересекал защищённую зону входа в спальню.
- **Исправление:** координата X комода изменена с 3,6 на 4,0 м.
- **Проверка:** все семь стартовых предметов проходят общую функцию проверки; видны в браузере.
- **Предотвращение:** сохранять тест валидности всей стартовой расстановки при изменении размеров и координат.

## E06 — Некорректная тестовая точка проверки входа

- **Описание:** тест ожидал ошибку входа, но получал ошибку внешней границы.
- **Причина:** стол при Z=3,0 м выходил за допустимую границу, и проверка останавливалась раньше.
- **Исправление:** тестовая координата Z изменена на 2,9 м, чтобы проверять именно свободный вход.
- **Проверка:** тест проходов проходит и проверяет нужную причину отказа.
- **Предотвращение:** изолировать проверяемое ограничение в тестовых данных.

## E07 — Дом обрезался бы при фиксированном масштабе на узком экране

- **Описание:** фиксированный zoom=46 не учитывал ширину мобильного viewport.
- **Причина:** начальная камера была рассчитана только на настольный экран.
- **Исправление:** начальный масштаб и минимальный zoom зависят от размеров canvas.
- **Проверка:** проверен скриншот 390 × 844; дом помещается, горизонтального переполнения документа нет.
- **Предотвращение:** включать узкий viewport в браузерные проверки.

## E08 — Браузерный тест не находил кнопку возврата камеры

- **Описание:** поиск кнопки по роли и имени «Вернуть камеру» завершался таймаутом.
- **Причина:** эта строка была только в title, доступное имя формировалось из текста «Исходный вид».
- **Исправление:** добавлен явный `aria-label="Вернуть камеру"`.
- **Проверка:** браузерный сценарий находит и нажимает кнопку по доступному имени.
- **Предотвращение:** использовать понятные доступные имена и проверять элементы через role/name.

## E09 — Нестабильное сравнение изображения камеры

- **Описание:** побайтовое сравнение PNG иногда сообщало об ошибке после возврата камеры, хотя визуально ракурс совпадал.
- **Причина:** скриншот canvas включает наложенные HTML-кнопки с меняющимся focus outline; также остаточные дробные значения damping и растеризации не гарантируют побайтовое равенство.
- **Исправление:** при сравнении временно скрыты HTML-оверлеи. Сравниваются декодированные пиксели: допускается менее 0,1% отличающихся пикселей с порогом 12 уровней на канал; вращение, сдвиг и zoom должны давать большую разницу.
- **Проверка:** браузерный тест проходит на dev и production preview: проверены изменения изображения при вращении, перемещении, zoom и возврат исходного вида с допуском.
- **Предотвращение:** сравнивать изображения с малым явным допуском, отделять состояние камеры от фокуса интерфейса.

## W01 — Размер production-модуля Three.js

- **Описание:** Vite предупреждает о chunk >500 КБ до gzip.
- **Причина:** 3D-движок составляет основную часть минимальной сцены.
- **Исправление:** выделены engine и scene chunks; пустой react chunk, появившийся при первоначальном разделении, удалён из конфигурации. Предупреждение о Three.js остаётся ограничением 0.1.
- **Проверка:** build завершается успешно; размер виден в отчёте Vite.
- **Предотвращение:** контролировать размер сборки, проверять скорость загрузки на реальных Telegram-устройствах перед следующей версией.

## E10 — Неполные исключения перед первой загрузкой в GitHub

- **Дата:** 19 октября 2026 года.
- **Описание:** `.gitignore` исключал зависимости и результаты сборки, но не исключал потенциальные `.env`, локальные настройки npm, приватные ключи, логи и временные файлы.
- **Причина:** первоначальная конфигурация покрывала только файлы, создаваемые текущим прототипом.
- **Исправление:** добавлены правила для `.env` и `.env.*` (кроме шаблонов `.env.example` и `.env.sample`), `.npmrc`, ключей и сертификатов, временных файлов, логов, кэша и coverage. Исходники и механики приложения не изменялись.
- **Проверка:** `git check-ignore` подтверждает исключения; шаблоны окружения не исключаются. Проверка 21 файла, предназначенного для коммита, не обнаружила совпадений с шаблонами токенов, приватных ключей и присвоенных секретов. `pnpm build`, `pnpm test` (5/5) и `pnpm format:check` проходят; предупреждение W01 остаётся прежним.
- **Предотвращение:** перед загрузкой проверять состав staged-файлов, правила игнорирования и признаки секретов; реальные учётные данные хранить вне исходного кода.

## E11 — Не настроен автор первого коммита

- **Дата:** 19 октября 2026 года.
- **Описание:** `git var GIT_AUTHOR_IDENT` завершился сообщением `Author identity unknown`; без исправления первый коммит создать нельзя.
- **Причина:** в доступной конфигурации Git отсутствовали `user.name` и `user.email`.
- **Исправление:** Git Credential Manager подтвердил сохранённую учётную запись `vitaminoviy`; публичный GitHub API подтвердил её ID `272043332` и имя `california`. Только в `.git/config` этого репозитория заданы имя `california` и адрес `272043332+vitaminoviy@users.noreply.github.com`. Глобальные настройки Git не менялись, токены не извлекались и не сохранялись в проект.
- **Проверка:** `git var GIT_AUTHOR_IDENT` успешно возвращает настроенного автора. `origin` указывает на `https://github.com/vitaminoviy/po-tipy-hozy.git`, текущая ветка — `main`.
- **Предотвращение:** проверять автора и адрес удалённого репозитория перед первым коммитом; использовать GitHub noreply для сохранения приватности личной почты.

## Prototype 0.2 — диагностика и исправления

### E12 — Избыточно ограниченная область расстановки

- **Дата:** 19 октября 2026 года.
- **Описание:** мебель нельзя было подвести к перегородке и поставить рядом с проходом даже без пересечения видимых стен.
- **Причина:** искусственный отступ от перегородки 0,23 м и прямоугольник прохода шириной 1,7 м дополнительно уменьшали каждую комнату; сетка жёстко округляла каждое движение.
- **Исправление:** сохранены реальные границы стен с небольшим запасом (0,12 м от оси перегородки); резерв у прохода сужен до 1 м. Движение свободное, к сетке 0,25 м притягиваются только координаты в пределах 3 см от линий. Если привязка нарушает допустимый отступ, используется свободная координата.
- **Проверка:** unit-тесты новых доступных позиций, запрета пересечения стен/прохода и сохранения допустимой свободной позиции проходят. Браузерные результаты фиксируются ниже.
- **Предотвращение:** хранить геометрические ограничения отдельно от комфортных межпредметных отступов; тестировать допустимые позиции у границ.

### E13 — Одинаковые грубые коллизии и недостаточный зазор

- **Дата:** 19 октября 2026 года.
- **Описание:** крупная мебель подходила почти вплотную; маленький декор занимал излишнюю прямоугольную область. Каталог не учитывал выступающие части комода и изголовья кровати.
- **Причина:** единая прямоугольная проверка с зазором 4 см для всех объектов, размеры задавались по основанию моделей.
- **Исправление:** добавлены категории «мебель», «напольный декор», «декор». Между мебелью требуется 22 см, между декором и мебелью — 8 см, между декором — 6 см. Растение и торшер используют окружности, расстояния до мебели рассчитываются до ближайшей точки прямоугольника; для прямоугольников используется евклидово расстояние между контурами. Размеры кровати/комода учитывают выступы, включая ручки комода (контур глубиной 0,78 м), растение — крону.
- **Проверка:** стартовая расстановка, граничные отступы, диагональные позиции, окружности и поворот габаритов проходят unit-тесты.
- **Предотвращение:** проверять размер модели и контур коллизии вместе; покрывать каждую пару типов и диагональные позиции тестами.

### E14 — Ковры недоступны для перемещения

- **Дата:** 19 октября 2026 года.
- **Описание:** оба ковра нельзя было выбрать, переместить или повернуть.
- **Причина:** ковры были статическими mesh внутри House, вне каталога и состояния предметов.
- **Исправление:** ковры перенесены в обычное состояние предметов с категорией floorDecor; они лежат на фиксированной высоте над полом. Коллизии с мебелью и другими коврами отключены в обе стороны, границы комнат сохраняются. Два небольших разнесённых уровня исключают мерцание при наложении ковров. Кнопка «Переместить» позволяет размещать выбранный ковёр независимо от перекрывающей его мебели.
- **Проверка:** unit-тесты перекрытия и границ проходят; браузерный сценарий проверил перенос ковра мышью, постановку под мебель, поворот предпросмотра, отказ пересечения перегородки и отмену.
- **Предотвращение:** интерактивные объекты хранить в общем каталоге, явно задавать слой и правила пересечений.

### E15 — Слабая читаемость сцены и выделения

- **Дата:** 19 октября 2026 года.
- **Описание:** модели, стены и пол сливались; старое выделение лежало ниже поверхности ковра и могло скрываться.
- **Причина:** высокое фоновое освещение, близкие светлые материалы, маркер на высоте 0,018 м при коврах выше него.
- **Исправление:** уменьшено фоновое освещение, усилен направленный свет, сделаны различимее оттенки пола, спальни и мебели. Новый контур и угловые отметки отображаются над коврами и видны при перекрытии; зелёный означает допустимость, красный — отказ. При переносе виден исходный контур и модель в новой позиции.
- **Проверка:** просмотрены скриншоты настольного и узкого экрана; новый маркер виден на ковре и вокруг кровати. Окончательные результаты сборки указаны ниже.
- **Предотвращение:** проверять контраст и маркеры на всех слоях пола, включая ковры и перекрывающие объекты.

### E16 — Устаревшие и некорректные ожидания тестов после изменения переноса

- **Дата:** 19 октября 2026 года.
- **Описание:** старый unit-тест ожидал обязательного округления 1,36 до 1,25. В новых браузерных тестах ожидалась ошибка отступа при фактическом пересечении и движение при смещении менее порога захвата.
- **Причина:** ожидания тестов не учитывали свободное движение и проекцию мирового смещения в экранные координаты; полное пересечение и нарушение зазора не были разделены.
- **Исправление:** unit-тест различает свободную координату и мягкую привязку. Браузерные случаи зазора и пересечения разделены; смещение для проверки свободного движения превышает 4 экранных пикселя. Микродвижение отдельно проверяет сохранение позиции при щелчке.
- **Проверка:** все 11 unit-тестов проходят; результат повторного браузерного прогона записывается ниже.
- **Предотвращение:** явно проверять порог начала drag в экранных координатах и независимо тестировать разные причины недопустимого размещения.

### E17 — Тест начинал drag до первого готового кадра

- **Дата:** 19 октября 2026 года.
- **Описание:** тест переноса ковра периодически не выбирал его первым щелчком сразу после навигации; остальные шаги и повторные попытки работали.
- **Причина:** видимый DOM canvas появлялся до первого кадра R3F и обновления мировых матриц геометрии; ожидание видимости canvas не гарантировало готовности raycasting.
- **Исправление:** сцена отмечает готовность после двух кадров, браузерные тесты ожидают этот признак до взаимодействия.
- **Проверка:** выполнена диагностика скриншота и обработчика событий; результат повторного браузерного прогона указан в итогах 0.2.
- **Предотвращение:** синхронизировать сценарии 3D-взаимодействия с отрисовкой сцены, а не только с появлением DOM-элемента.

### E18 — Повторная инициализация Telegram при перемещении

- **Дата:** 19 октября 2026 года.
- **Описание:** выбор предмета, поворот и обновления draft повторно вызывали `ready()`, `expand()` и `disableVerticalSwipes()`.
- **Причина:** инициализация bridge находилась в одном эффекте с обработчиком клавиатуры, зависящим от callback поворота; callback меняется вместе с выбранным предметом и предпросмотром.
- **Исправление:** инициализация bridge вынесена в отдельный эффект при монтировании; обработчик клавиатуры продолжает получать актуальный предмет.
- **Проверка:** в браузерный сценарий с заглушкой Telegram добавлена проверка неизменности числа вызовов bridge после выбора предмета; результаты итогового прогона указаны ниже.
- **Предотвращение:** не объединять одноразовую инициализацию внешних API с эффектами интерактивного состояния.

### E19 — Лишний контур исходной позиции при переносе

- **Дата:** 19 октября 2026 года.
- **Описание:** одновременно с текущим предпросмотром показывался серо-синий контур прежнего положения; при небольших смещениях два контура накладывались.

### E20 — Разрыв привязки и переключение координат коллизиями

- **Дата:** 19 октября 2026 года.
- **Описание:** у края мягкой привязки предпросмотр скачком менял положение. Рядом с мебелью дополнительное переключение между snapped и raw давало колебания.
- **Причина:** snap использовал жёсткий порог 3 см. До исправления движение координаты с 1,2799 до 1,2801 м меняло результат с 1,25 до 1,2801 м — скачок 3,01 см на ввод 0,2 мм. На границе коллизии при вводе Z=1,0149/1,0151 результат менялся с 1 до 1,0151 м из-за проверки допустимости внутри placementCandidate.
- **Исправление:** притяжение непрерывно и монотонно: зона захвата 1,2 см и кубический переход к свободному движению до прежней внешней границы 3 см; производная согласована на краях. Коллизии больше не переключают координаты: они задают цвет, отказ установки и откат. Отменён подъём модели на 8 см при захвате — при начале/конце drag высота не скачет.
- **Проверка:** 12/12 unit-тестов проходят, включая 6000 последовательных отсчётов на нескольких положительных и отрицательных ячейках и прежние границы скачков. Сборка и TypeScript проходят; браузерный результат указан ниже.
- **Предотвращение:** тестировать не только совпадение с сеткой, но и непрерывность/монотонность переходов; отделять вычисление позиции от обратной связи о коллизиях.

### E21 — Избыточные пересекающиеся поверхности маркера

- **Дата:** 19 октября 2026 года.
- **Описание:** маркер содержал полупрозрачные объёмные боковины, пересекающиеся в углах, и дополнительные вертикальные стойки; часть геометрии записывала глубину при отключённом depthTest.
- **Причина:** рамка собиралась из нескольких закрытых box-мешей вместо единой плоской геометрии. Наложения прозрачных граней и исходного маркера усложняли смешивание и могли усиливать визуальное мерцание. Z-fighting с полом/коврами не подтверждён: маркер уже находился выше их поверхностей.
- **Исправление:** рамка заменена одной плоской ShapeGeometry с отверстием (или RingGeometry для круглых предметов). Заливка занимает только внутреннюю область, рамка непрозрачна; оба материала не записывают глубину. Рамка на 2 мм выше заливки, весь маркер выше пола и ковров; вспомогательные стойки удалены.
- **Проверка:** сборка и TypeScript проходят; последовательности кадров и неподвижный предпросмотр проверяются браузерным сценарием ниже.
- **Предотвращение:** избегать пересекающихся прозрачных поверхностей и записи глубины служебной геометрией; проверять кадры при движении и при остановке указателя.

### E22 — Излишне широкий переход привязки при проверке фикса

- **Дата:** 19 октября 2026 года.
- **Описание:** первая версия плавного перехода до 6 см изменяла X кровати с 2,80 на 2,79 м даже при переносе только вдоль Z.
- **Причина:** зона притяжения была шире исходных 3 см; прежняя свободная координата попадала в новую зону влияния.
- **Исправление:** сохранена исходная внешняя граница 3 см, непрерывный переход начинается после зоны захвата 1,2 см. Действующие браузерные ожидания позиции кровати сохранены.
- **Проверка:** исходный браузерный сценарий выявил регрессию; после исправления проводится полный прогон ниже.
- **Предотвращение:** при исправлении плавности сохранять диапазон влияния привязки; проверять отсутствие поперечного сдвига при переносе вдоль одной оси.

### E23 — Полосы / мерцание дивана, кресла и кровати — ИСПРАВЛЕНО в 0.3.3, проверено в Chrome

- **Дата:** 19 октября 2026 года — исходное сообщение о диване; 20 октября 2026 года — расширение на кресло/кровать, диагностика и исправление. До 0.3.3 причина действительно оставалась неизвестной; прежние итоги релизов ниже отражают состояние на их дату.
- **Описание:** при вращении камеры на подлокотниках и стыках дивана/кресла появлялись полосы; сходный дефект найден на переднем стыке матраса и покрывала кровати.
- **Установленная причина:** z-fighting отдельных BoxGeometry с совпадающими наружными гранями одинаковой ориентации и ненулевой площадью перекрытия: 9 пар у дивана, 13 у кресла, 1 у кровати. Например, основание/подлокотники дивана делили переднюю и заднюю плоскости Z=±0,55, кресла — наружные плоскости X/Z=±0,5, матрас/покрывало — Z=1,25 при Y=0,72–0,75. На диване/кресле полосы сохранялись при отключённом receiveShadow и пересборке материалов; нормали корректны, материалы непрозрачны, depthTest/depthWrite включены. Внутренние пересечения без совпадения наружных плоскостей не объявляются самостоятельной причиной.
- **Исправление:** основание дивана уменьшено с 2,5×1,1 до 2,46×1,08 м; основание кресла — с 1×1 до 0,98×0,98 м. Подлокотники состыкованы со спинками без перекрытия задних граней: глубина 0,86/0,76 м и центр Z=0,12. Глубина покрывала увеличена с 1,8 до 1,82 м, чтобы передний торец выступал над матрасом на 1 см. Высоты, цвета, основные внешние размеры и прочие детали сохранены. Свет, shadow bias/normalBias, прозрачность и глобальная проверка глубины не менялись.
- **Проверка:** аналитический тест воспроизводит прежние 9/13/1 пар, после исправления — 0/0/0. Проверены наружные нормали, треугольники и габариты. В диагностике получены 36 сравнительных кадров (до/после × три модели × три ракурса × с тенями/без теней), отдельно просмотрены проблемные участки крупным планом. Новый сценарий Chrome сохраняет 24 кадра с четырёх сторон на двух масштабах через реальные СКМ/ПКМ/колесо; просмотренные спинки, подлокотники, сиденья, матрас, подушки, каркас и изголовье не имеют исходных полос. Это подтверждает исправление воспроизведённой причины в Chrome, но не является гарантией отсутствия любых дефектов на всех GPU/Telegram WebView.
- **Предотвращение:** не совмещать перекрывающиеся однонаправленные наружные грани независимых деталей; разрешать обычные стыки с противоположными нормалями. Добавлены регрессионные тесты геометрии и многовидовой сценарий. Временный доступ к рендереру/сцене после диагностики удалён.

### E24 — Ориентация при переносе между повёрнутыми поверхностями

- **Дата:** 19 октября 2026 года.
- **Описание:** при разработке переноса мелкого декора обнаружена возможность ошибочного прибавления угла прежней мебели к локальному углу уже новой поверхности.
- **Причина:** активный drag хранил исходный surfaceId, но использовал rotation из текущего предпросмотра после смены поверхности.
- **Исправление:** при вычислении кандидата используется весь текущий attachment (surfaceId и локальная rotation вместе), мировой угол сохраняется при смене родителя.
- **Проверка:** тесты преобразований для всех четырёх поворотов проходят; в браузере книга сохраняет мировой угол 180° при последовательном drag с повёрнутой тумбы на комод и при движении по новой поверхности, включая undo/redo.
- **Предотвращение:** считать координаты и ориентацию attachment единой локальной системой; не смешивать поля от разных родителей.

### E25 — Численное изменение анимации при нулевом delta

- **Дата:** 19 октября 2026 года.
- **Описание:** тест неподвижного шага обнаружил изменение 0,3 на 0,30000000000000004 при delta=0.
- **Причина:** формула экспоненциального приближения выполняла арифметику с плавающей точкой даже при отсутствии прошедшего времени.
- **Исправление:** при нулевом/отрицательном delta, нулевой скорости или совпадении с целью возвращается исходное значение без вычислений.
- **Проверка:** тест неподвижного шага, монотонного выдвижения, обратного движения и ограничения длинного кадра проходит; оба анимированных объекта проверены в Chrome.
- **Предотвращение:** явно проверять граничные условия временных функций, а не только обычный шаг кадра.

### E26 — Точное имя кнопки стен в новых браузерных тестах

- **Дата:** 19 октября 2026 года.
- **Описание:** новые тесты взаимодействий останавливались на поиске кнопки «Скрыть стены».
- **Причина:** доступное имя включает существующую иконку ▱; точное сравнение имени не совпадало. Аналогичная особенность доступного имени уже отмечалась в E08.
- **Исправление:** общий helper новых сценариев использует такой же поиск по роли и тексту, как существующие тесты дома, без требования exact для этой кнопки.
- **Проверка:** все четыре новых браузерных сценария проходят после исправления helper; игровые обработчики для этой ошибки не менялись.

### E27 — Тест переносил книгу вместо тумбы

- **Дата:** 19 октября 2026 года.
- **Описание:** сценарий переноса тумбы с книгой получал прежнюю позицию тумбы; перенос книги в итоге откатывался.

- **Проверка:** проходит сценарий перемещения тумбы с книгой, поворота родителя, повторного переноса книги на комод и восстановления attachment через undo/redo.
- **Предотвращение:** для теста переноса мебели выбирать видимую часть её геометрии; отдельно проверять выбор мелких предметов и самой мебели.

### E30 — Залипание пошагового ввода в зоне захвата сетки

- **Дата:** 19 октября 2026 года.
- **Описание:** повторное прибавление малого клавиатурного шага к уже привязанной координате не позволяло выйти из зоны захвата; например, `snap(0 + 0.005)` каждый раз возвращает 0.
- **Причина:** накопление движения в snapped-координатах теряет дробную часть каждого кадра. Аналогичная опасность при накоплении недопустимых шагов позволяла бы пройти препятствие.
- **Исправление:** отдельный raw-аккумулятор и независимый предпросмотр с прежней непрерывной функцией snap. Траектория проверяется шагами до 2,5 см; из допустимого состояния недопустимые шаги не накапливаются. Если пользователь выбрал уже красную позицию мышью/кнопкой ящика, её можно вывести из пересечения, но нельзя подтвердить.
- **Проверка:** unit-тесты удержания при 30/144 FPS, выхода из сетки, точной скорости и 60 повторных упоров в препятствие проходят. Chrome проверяет клавиатурный перенос, красную позицию в ящике, Enter/Esc и один шаг истории на сессию.
- **Предотвращение:** не использовать визуальную привязку как интегратор ввода; отдельно хранить разрешённый исходный шаг и цвет предпросмотра.

### E31 — Неполный вертикальный габарит декоративной коробки

### E32 — Недоступный системный Python при служебном редактировании

### E33 — Ограничение камеры до применения инерционного сдвига

- **Дата:** 19 октября 2026 года.
- **Описание:** браузерный тест плоскости движения получил Y=2,638458742809402e-24 вместо 0 после ПКМ. Та же последовательность могла слегка выходить за ограничение X/Z; сброс камеры мог сохранять остаток инерции.
- **Причина:** `OrbitControls.update()` применял остаточный pan после ограничения target. Сброс позиции не очищал накопленные delta OrbitControls.
- **Исправление:** границы X/Z и Y=0 применяются после обновления инерции; camera и target сдвигаются вместе. Home/кнопка сброса очищают delta через reset с временно отключённым damping. Движение клавиатуры использует точный интеграл экспоненциального ускорения.
- **Проверка:** прежнее строгое сравнение Y с нулём теперь проходит в Chrome; проверяются границы, ракурс после ПКМ и Home. Unit-тест сравнивает путь ускорения/торможения при 30/60/144 FPS с погрешностью меньше 1e-10.
- **Предотвращение:** накладывать ограничения после всех источников движения; при reset очищать состояние контроллера, а не только координаты камеры.

### E34 — Раздельное время анимации ящика и вновь размещённого содержимого

- **Исправление:** одна таблица выдвижения для всех ящиков обновляется раз за кадр. Геометрия ящика, его содержимое и зона определения поверхности читают одно значение. Закрытое содержимое исключается из отрисовки и raycasting, записи и локальные координаты остаются в истории.
- **Проверка:** Chrome проверяет размещение в уже открытые ящики, три повторных цикла открытия/закрытия, извлечение, перенос родителя и undo/redo; число предметов остаётся 13. - **Предотвращение:** для геометрически связанных объектов использовать общий источник анимации, а не совпадающие независимые таймеры.

- **Проверка:** реальный BAT успешно запущен из `docs` в Windows 11; дополнительный тест копирует его и helper в путь с пробелами, `&` и кириллицей и получает ожидаемое сообщение об отсутствующих зависимостях.

## Prototype 0.3.4 — повторный запуск и изолированные проверки

### E43 — BAT отклонял уже запущенную игру как занятый порт

- **Дата:** 20 октября 2026 года.
- **Описание:** повторное нажатие `Запустить игру.bat` показывало ошибку занятого 5173, хотя игра была доступна.
- **Установленная причина:** launcher вызывал `assertFreePort` до распознавания приложения. Прежний случайный endpoint готовности принадлежал только одному запуску, поэтому следующий launcher не мог распознать уже работающий экземпляр; обычный `pnpm dev` такого endpoint не имел.
- **Исправление:** Vite dev plugin предоставляет постоянный `/__quiet-home_identity` с именем репозитория, версией протокола и SHA-256 канонического пути папки. Путь и секреты не публикуются, production-сборка не содержит endpoint. Совпадающий сервер повторно используется; посторонний сайт, даже с таким же заголовком, и другая папка отклоняются. Новый сервер запускается через существующий `pnpm dev` с loopback/strictPort; ожидание маркера, HTML и входного модуля предшествует единственному открытию браузера. Межпроцессный lock в игнорируемом `node_modules/.cache` сериализует одновременные запуски. Чужие и повторно используемые процессы не завершаются. Остановка через helper затрагивает только созданное им дерево процесса.
- **Проверка:** 13 интеграционных проверок launcher, в том числе реальные BAT-сценарии A/B/C/Г на Windows 11 build 26300, проходят. Все BAT-вызовы используют `--no-browser`; открытие проверено подставным callback ровно один раз на запуск после готовности. Проверены одновременный старт, IPv4/IPv6, чужой маркер, недоступная страница при правильном маркере, ошибка Vite, отсутствие зависимостей, пробелы/`&`/кириллица в пути, отказ callback открытия, сохранение сервера при повторном запуске. Повторно запущен реальный BAT из `docs` на 5173: существующая игра распознана без второго сервера. Windows 10 и фактическое открытие личного браузера в этом обновлении не проверялись.
- **Предотвращение:** сохранять публичный протокол идентификации для всех способов dev-запуска, проверять повторный и конкурентный старт отдельно от свободного порта; автоматические проверки никогда не должны вызывать системный браузер.

### E44 — Ошибка соединения IPv6 ошибочно считалась свободным портом

- **Дата:** 20 октября 2026 года.
- **Описание:** при разработке проверки порта тест с существующим IPv6 HTTP-сервером сначала не отклонил запуск.
- **Установленная причина:** пробное соединение Node с `::1` в этой Windows-среде вернуло `EACCES`, хотя сервер успешно слушал этот адрес. Первая реализация считала любую ошибку соединения отсутствием слушателя. Причина ограничения доступа на уровне Windows не установлена; системные настройки не менялись.
- **Исправление:** только `ECONNREFUSED` прямо означает отсутствие соединения; другие ошибки дополнительно проверяются эксклюзивной попыткой привязки. Невозможность подтвердить безопасный адрес приводит к отказу открытия страницы. Поддерживается отсутствие IPv6.
- **Проверка:** регрессия с настоящим слушателем `::1` проходит; чужой IPv6-порт не открывается, свободные порты и существующий IPv4-сервер проекта успешно обрабатываются. В первом неудачном тесте использовался только подставной callback; личный браузер не запускался. Оставшееся дерево только этого теста остановлено при очистке.
- **Предотвращение:** различать отказ соединения, запрет доступа и отсутствие семейства адресов; не считать все сетевые ошибки эквивалентными свободному порту.

### E45 — Прежние браузерные ожидания не подходили программному рендереру Headless Shell

- **Дата:** 20 октября 2026 года.
- **Описание:** первый прогон отдельного Chromium выявил расхождение ракурса после фиксированной паузы, уже завершённую промежуточную анимацию на screenshot и тайм-аут длинного сценария хранения.
- **Установленная причина:** Chromium Headless Shell 156 по умолчанию выбрал ANGLE Vulkan SwiftShader. Диагностика через RAF и WEBGL_debug_renderer_info показала 19 кадров за 1545 мс (около 12 FPS). При ANGLE Direct3D11 на NVIDIA RTX 4060 Ti — 91 кадр за 1504 мс (около 60 FPS). Существующие фиксированные паузы и скриншоты зависят от скорости тестового рендерера.
- **Исправление:** только в Windows-конфигурации Playwright добавлен `--use-angle=d3d11`; остаются отдельный Chromium, headless и временный профиль. Переключение на установленный Chrome через PLAYWRIGHT_CHANNEL удалено. Два прежних теста камеры всё ещё считывали незавершённую инерцию после фиксированной паузы: теперь общий helper ожидает три стабильных замера координат с прежними строгими допусками assertions. Перед проверкой ввода текста также ожидается завершение сброса Home: прежний тест мог снять старую ограниченную позицию до React-effect и затем получить смещение ровно 5 м после сброса. Рендер, материалы, анимации и управление игры не менялись.
- **Проверка:** отдельно исправленный сценарий камеры проходит; визуальный сценарий со всеми 24 ракурсами проходит. В промежуточном прогоне после выбора GPU прошли 15/17 сценариев; оставшиеся два исправлены ожиданием фактического завершения камеры и Home. Окончательный полный результат указан в итогах ниже.
- **Предотвращение:** проверять фактический рендерер изолированного браузера при переносе тестов между средами; не компенсировать настройку тестового окружения изменением игровых механик.

### E46 — Отдельный полный Chromium недоступен для запуска в этом окружении (НЕРЕШЕНО)

### E47 — Мелкие вещи слишком рано получали красный предпросмотр

- **Дата:** 20 октября 2026 года.
- **Описание:** расчётная область чашки и запас на столешницах ограничивали позиции раньше видимого соприкосновения; вне столешницы отображалась ошибка отсутствия поверхности, даже вдали от мебели.

### E48 — Недопустимый drag возвращался в далёкую исходную позицию

- **Дата:** 20 октября 2026 года.
- **Описание:** отпускание после длинного переноса в красной зоне возвращало предмет к началу жеста, даже если рядом уже была допустимая позиция.
- **Установленная причина:** pointerup проверял только окончательный кандидат и при ошибке сбрасывал draft; промежуточные допустимые состояния не сохранялись.
- **Исправление:** сессия переноса хранит исходный предмет и копию последнего допустимого кандидата, включая поворот, surfaceId и drawerIndex. Все пути изменения draft обновляют эту копию без записи истории. При отпускании конечная красная позиция заменяется последней допустимой, либо исходной; снимок повторно проверяется перед одним commit. Esc/смена режима/undo/redo очищают сессию. Enter/щелчок в режиме выбора позиции сохраняют прежний отказ подтверждать красный предпросмотр.

Браузерные тесты мебели и чашки подтверждают точное совпадение с последним зелёным замером, один undo назад, redo, отсутствие лишнего действия при возврате в исходную позицию и очистку старой сессии после Esc. Старые проверки полного отката обновлены под требуемое поведение.
- **Предотвращение:** хранить сессию отдельно от истории, фиксировать единственное итоговое изменение и проверять повторные жесты после отмены.

## Prototype 0.3.6 — контакт мелких вещей и мягкие поверхности

### E52 — Отсутствовали опорные поверхности мягкой мебели

- **Дата:** 20 октября 2026 года.
- **Описание:** чашка, книга и коробка не крепились к кровати, дивану и креслу.
- **Установленная причина:** support и перебор поверхностей распознавали только catalog.surface для трёх жёстких столешниц и drawerIndex. Матрас/покрывало/сиденья не имели опорных зон, поэтому луч под курсором выбирал пол, а попытка назначить мягкую мебель родителем отклонялась.
- **Исправление:** добавлен небольшой модуль placementGeometry с SurfaceZone, получаемыми из существующих частей upholsteredParts. Кровать предоставляет покрывало, складку и матрас; диван — две подушки сиденья; кресло — сиденье. Новое необязательное поле surfaceZone хранит идентификатор части. Локальные X/Z переводятся в мировые с учётом смещения зоны и поворота родителя. Технический зазор — 1 мм; выход за край, подушки, спинки, подлокотники и поднятая складка проверяются составными объёмами. Вещи разных зон одного дивана сравниваются в мировых координатах. При переносе на пол, жёсткую поверхность или в ящик ключ мягкой зоны очищается. История и сессия последней допустимой позиции используют прежние Item-снимки, без отдельного действия на каждый кадр.
- **Проверка:** unit-тесты разрешают все три маленьких вида на каждой мягкой мебели, проверяют точный Y относительно геометрии, края/выступы, разные зоны дивана, четыре поворота, следование за перемещением родителя и rollback/undo/redo с сохранением surfaceZone. Просмотрены близкие кадры каждой мягкой поверхности. Итог полного прогона указан ниже.

### E72 — Сервер запуска зависел от открытого CMD

Старое ожидание удержания CMD обновлено под новое требование.

### E73 — PID-файл не подтверждает идентичность живого процесса

- **Дата:** 21 октября 2026 года.
- **Описание:** при аудите прежней блокировки выявлено: существование PID считалось достаточным, чтобы ждать другой запуск. Если PID переиспользован после аварии/перезагрузки, такая запись могла ошибочно блокировать запуск. Для нового BAT остановки завершение по одному записанному PID было бы небезопасно.
- **Установленная причина:** файловая блокировка содержала только число PID и проверяла process.kill(pid, 0), без идентификатора поколения процесса. Реальная перезагрузка/принудительное переиспользование системного PID не выполнялись; опасный случай воспроизведён старой записью с PID живого тестового процесса.
- **Исправление:** на Windows блокировка старта/остановки заменена именованным каналом ОС, автоматически освобождаемым при завершении. Dev-маркер и атомарная запись содержат случайный instance, PID и отпечаток проекта; остановка дополнительно требует локальный случайный ключ. PID никогда не используется как цель завершения при чтении записи. Устаревшая запись без живого сервера безопасна и перезаписывается при следующем старте; несовпадение с живым сервером вызывает отказ.
- **Проверка:** живой посторонний PID, чужая папка/instance, неправильный ключ и повреждённый JSON не останавливают сервер/чужой процесс. Чужая HTTP-страница сохраняется после обоих BAT даже с подложенной PID-записью. Старая блокировка с живым PID не мешает Windows-старту. Одновременные фоновые старты создают один сервер; повторное использование и аварийный перезапуск проходят. Маркер и лог не содержат ключ остановки.
- **Предотвращение:** сохранять тесты старых/подменённых записей и конкурентного старта; различать PID как диагностическое свидетельство и подтверждённую принадлежность экземпляра; не добавлять taskkill/Stop-Process по PID из файла или порта.

### E74 — Повторный запуск обходил блокировку остановки

- **Дата:** 21 октября 2026 года.
- **Описание:** при проверке конкурентных действий выявлено, что быстрый путь повторного использования уже работающего сервера не брал блокировку и мог пересечься с его остановкой.
- **Установленная причина:** прежняя блокировка захватывалась только в ветке создания нового процесса, после проверки маркера.

- **Проверка:** тест удерживает канал как активная остановка и подтверждает, что повторный запуск не завершается до его освобождения; затем возвращает тот же сервер. Повторный набор запуска/остановки — 22/22, без новых экземпляров и открытия личного браузера.

### E77 — Последний запланированный React-кадр мог догонять отпускание

### E79 — Перенос мышью терял координаты при одновременном вращении Q/R — исправлено

- **Дата:** 21.10.2026.
- **Описание:** при удержании Q/R во время перетаскивания угол менялся, но после перемещения указателя мебель возвращалась к прежним координатам. Последовательный тест «перенос, затем поворот» проблему не обнаруживал.

Обработчик указателя и подтверждение также читали отложенные props и могли потерять последний угол/положение. - **Исправление:** введён один синхронный `draftPose` и стабильный getter. Центральный setDraft обновляет его до React-состояния и сохраняет валидную полную позу. RAF, pointermove, keyup, подтверждение ЛКМ/Enter читают актуальный снимок. Вращение меняет угол последней позы, движение сохраняет последний угол; фиксированный world-offset захвата не пересчитывается при вращении. История по-прежнему создаётся только при завершении жеста. Отпускание ЛКМ после поворота без перемещения тоже подтверждает изменённый угол.

В одном интервале удерживаются кнопка мыши и клавиша, указатель несколько раз перемещается; проверяются изменения координат и угла, неподвижность после отпускания Q/R, продолжение переноса, один undo/redo и привязки книги/чашки. Сохранять сценарии одновременного, а не последовательного ввода. Скорость 7,5°/140 мс и 75°/с, SAT/2 см, модели, материалы, освещение, камера, уборка и запуск не изменялись. ### E82 — Отложенный pointermove мог перекрыть явный выбор ящика — исправлено

- **Дата:** 21.10.2026.
- **Описание:** при полном регрессионном прогоне после введения очереди controls-storage обнаружил «На полу» вместо «В ящике 3» после кнопки размещения коробки и Enter.

- **Предотвращение:** явно различать очередность событий указателя и команд выбора позы; проверять очередь на границах подтверждения, отмены и интерфейсных действий, не исправлять регрессию удалением старого теста.

### E101 — тёмный ореол вокруг мягких краёв краски

- **Описание:** граница мазка местами темнее и исходной стены, и непрозрачной краски. Воспроизведено на двух разных исходных стенах и трёх цветах.
- **Подтверждённая причина:** RGBA CanvasTexture одновременно использовалась как цветовая карта и прозрачность. Хотя ImageData содержала белый RGB даже при alpha=0, Canvas2D при записи теряет RGB полностью прозрачного пикселя: тест [255,255,255,0] → чтение [0,0,0,0]. При линейной/mip-фильтрации соседний чёрный RGB попадает в цветовой результат; затем прозрачность дополнительно смешивает его со стеной. Белая инициализация в 0.6.2 не устраняла эту потерю. Кисть изменяет только покрытие через max, повторное затемнение ею не создаётся; дополнительных пересекающихся слоёв и ошибочного изменения палитры не обнаружено.
- **Исправление:** покрытие передаётся как alphaMap, цвет остаётся в MeshStandardMaterial.color. DataTexture хранит RGB=покрытие, служебный alpha всегда 255; Three.js использует зелёный канал alphaMap. Данные NoColorSpace, premultiplyAlpha=false, ориентация flipY сохранена. RGB маски вообще не умножает цвет краски. Разрешение и фильтры 0.6.2 сохранены; сглаживание и порог не изменены. Текстура переиспользуется, обновляется лишь при изменении, освобождается при удалении слоя; Canvas/ImageData для стен больше не нужны.
- **Проверка причины:** одинаковый короткий мазок до исправления дал затемнение ниже минимума двух цветов (RGB, 0–255): гостиная кремовый/шалфейный/терракотовый — 20/1/6; спальня — 15/10/19. После исправления во всех шести случаях — 0. Сравниваются реальные пиксели снимка сцены, не только процент покрытия. Проверка повторного прохода требует идентичных пикселей края. Снимки сохранены в artifacts/063-before и artifacts/063-after; проверены также пересечения, диагонали и круговые движения в обычном масштабе и при приближении.
- **Предотвращение:** держать покрытие отдельно от цвета; не полагаться на скрытый RGB прозрачного Canvas. Добавлены три unit-теста хранения/фильтров/размеров и шесть браузерных проверок цветового перехода. Пиксельный допуск 3 учитывает округление рендеринга, не скрывает исходный провал до 20.

## Prototype 0.7 — 21.10.2026

### E103 — кнопки подтверждения смены покрытия не принимали клики

- **Причина:** новая небольшая область подтверждения использовала прежний класс пассивной подсказки с pointer-events:none. Сценарий фиксировал клики в Canvas вместо кнопки.
- **Исправление:** интерактивность включена только у контекстного role=alert; на узком экране разрешён перенос текста/кнопок. Esc, смена режима, открытие записки и undo/redo закрывают устаревший запрос. Никаких постоянных панелей не добавлено.
- **Проверка:** сохранение материала без сброса, явный сброс, undo/redo сброса и последующая укладка другого материала проверяются браузером. Произвольного удаления прогресса нет.
- **Предотвращение:** разделять пассивные подсказки и контекстные элементы управления, проверять настоящий pointer-клик без force.

### E104 — свободная по координатам площадь недоступна из-за перекрытия стенами/мебелью

- **Причина:** первый расчёт доступности по одним footprint учитывал свободный пол за видимой перегородкой; с одного ракурса завершение требовало невидимых участков. Первоначальная проба сканирования также использовала движение СКМ в сторону низкого ракурса, а не верхнего. При исправленной камере оставшиеся частично видимые углы давали около 91,6% доступного покрытия и не достигали первоначальных 93%.
- **Исправление:** в начале жеста доступная площадь оценивается пятью лучами камеры на элемент; учитываются видимость родителей, окклюзия и экран. Кеш зависит от камеры, предметов, материала, комнаты, стен и состояний мусора. При финальном ревью добавлена инвалидация после утилизации мусора: один массив мебели не отражает исчезновение его 3D-моделей. Повторная укладка после уборки проверяется тем же смешанным сценарием. Порог выбран 90% доступной площади в разрешённом диапазоне 90–95%, плюс минимум 40% всей площади реально установленными элементами. Завершение выполняется только при новом зафиксированном жесте, не от поворота камеры или таймера. Значения доступности проверяются по длине, конечности и площади элемента. В записке процент всегда выводится из уложенной площади, а не из независимого счётчика.
- **Проверка:** полные ремонты обеих комнат с двух ракурсов без перестановки мебели; сохранность прогресса, автоукладка скрытых частей, отмена/повтор завершения. Unit-тест исключает завершение от двух элементов даже при 100% покрытия узкой видимой зоны.
- **Предотвращение:** оценивать доступность взаимодействия с учётом реального raycast, сохранять минимальную долю ручной работы и проверять несколько ракурсов. Оценка остаётся дискретной; пиксельно точная видимость не заявляется.

### E105 — фикстуры новых тестов и снимки во время перехода записки

- **Причина:** помощник выбора ошибочно ожидал активный инструмент после повторного клика, хотя повтор снимает выбор. Тест квадратной внутренней плитки включал подрезанные крайние ряды. Узкий literal-тип координат губки не позволял присвоить координаты валика. Снимок сразу после закрытия записки фиксировал её 250-мс переход.
- **Исправление:** проверяются активация и снятие отдельно; у внутренней плитки фильтруются обе стороны, координаты типизированы кортежем чисел, снимок делается после окончания перехода. Все проверки сохранены; полезные тесты не отключались.
- **Проверка:** набор укладки проверяет четыре размера экрана, частичные/полные состояния, смешанную историю, реальные клики и геометрию. Тесты рядов используют допуск double вместо точного равенства 0,32.
- **Предотвращение:** отличать подрезанные элементы от внутренних, проверять обратное действие инструмента и ждать завершения визуального перехода перед снимком.

### E106 — граница платформы образцов и тонкая полоса старого пола

- **Причина:** первоначально отступ новой платформы считался от ступени, но не от полного основания дома, заканчивающегося на Z=3,75. Также использовалась толщина дверных стоек вместо 18-см тела перегородки, оставляя вдоль неё 2,5-см полосу старого пола.
- **Исправление:** платформа образцов сдвинута вперёд; её задний край Z=3,95 отделён от основания 20 см, левый край X=3,6 от ступени X=3,4 — 20 см. Образцы имеют минимум 20 см до края своей площадки. Пол подрезается по внутренним граням тела перегородки X=±0,09; стойки перекрывают тонкий слой у своего основания и не меняются. Проход делится на X=0, внешние стены/порог и высоты мебели сохранены.
- **Проверка:** проверки площади/непересечения сетки обеих комнат, полных габаритов площадки/образцов и кадрирования четырёх экранов; визуальный осмотр стыков, ковров и проёма.
- **Предотвращение:** сверять границы с полной геометрией House, не только с центрами предметов или более толстой отдельной деталью.

### Повтор прежней E97 при регрессии фонового запуска

- В двух ранних полных unit-прогонах повторился отказ окончательной проверки идентичности сервера сразу после аварийного завершения/перезапуска собственного тестового процесса. Порт и PID принадлежат исключительно временному тестовому серверу; игра на 5173 не останавливалась.
- Причина окончательно не установлена. В изолированной диагностике 12 повторных сценариев перезапуска прошли; видны обычные ECONNREFUSED/ECONNRESET при прекращении старого процесса и EACCES для IPv6-пробы Windows. Этого недостаточно для утверждения причины финального отказа. Временные диагностические сообщения убраны, исходные скрипты запуска восстановлены побайтно; BAT не менялись. E97 остаётся открытой, исправление не заявляется.
